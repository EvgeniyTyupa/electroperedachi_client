# Паспорт рейвера: изменения в трёх проектах

По решению владельца, возврат билетов не предусмотрен политикой проекта. Клиентский и административный сценарии возврата не входят в задачи этой версии.

## Что реализовано в коде

- Next.js: `/passport`, вход по коду на email, существующие билеты и QR-коды, баланс и резерв, история баллов, Instagram-заявки, подписка на анонсы, выход. Украинский и английский интерфейсы. Ссылка в общей навигации.
- В формах покупки, которые используют текущий `ticketCart`, добавлено применение баллов. Итоговую цену, промокод, групповую скидку и лимит списания проверяет сервер.
- React-админка: `/passport` — правила программы, модерация контента, балансы и корректировки с причиной, предварительный расчёт и начисление за прошлые оплаты. `/campaigns` — редактор текстового письма, предпросмотр, черновики, тестовая отправка, аудитория за 180 дней, очередь и статусы.
- Express/MongoDB: отдельные клиентские сессии, ограничения попыток входа, проверка origin, журнал операций с уникальными источниками, транзакционное резервирование, повторяемое начисление, проверка подписи и реквизитов LiqPay, защита публичной выдачи билетов и экспорта пользователей.
- Генерация билетов для новых заказов использует `paymentId + sequence`, чтобы повтор обработки не создавал второй набор билетов. Цена билетов распределяется в копейках и в сумме соответствует оплаченной сумме заказа.
- Бесплатные билеты **за 0 грн не дают баллов**. За заказ, полностью оплаченный баллами, новая награда также равна нулю. Бесплатные заказы исключены из сегмента платящих клиентов для рассылок.
- Исторические платежи проверяются в LiqPay. Один и тот же платёж не начисляется повторно. Спорные записи, нулевая сумма и отсутствие надёжной даты завершения оплаты попадают в список пропусков.

## Что находится в архиве

`raver-passport-changes.zip` содержит только новые/изменённые файлы в папках `client/`, `admin/`, `back/`. Их нужно перенести в соответствующие проекты с сохранением путей. Список файлов — `changed-files.txt`.

Архив не содержит `.env`, реальных ключей, базы клиентов, `node_modules` и сборок с тестовыми данными. Исходные проекты на Desktop не перезаписаны. Изменённые рабочие копии находятся в папке этого чата `work/projects/`.

## Результат проверок

- Синтаксис всех 398 JS/JSX-файлов проходит проверку.
- Пять групп тестов правил: нулевая цена/оплата баллами, лимиты, округление цен билетов, Instagram-ссылки, подпись/сумма/валюта/номер заказа/продавец.
- Интеграционные проверки в одноразовой MongoDB replica set: код и одноразовое использование, сессия, origin, чужой билет, одновременное начисление одной оплаты, первое начисление без созданного кошелька, одновременные резервы без превышения баланса, освобождение резерва, повтор ссылки и решения модерации, повтор создания заказа, бесплатный заказ и оплата на 100% баллами без новой награды, сегмент подписчиков и защита админки, выход. Проверено также, что повтор запуска кампании отклоняется, HTML в письме экранируется, а отписка после постановки в очередь предотвращает отправку.
- Админка собрана. ESLint-плагин сборки был отключён, поскольку кэш установленных зависимостей лежит вне доступной для записи папки; проверка синтаксиса выполнена отдельно. Есть предупреждения сторонних source maps и размера существующего bundle.
- Клиент собран с пустым тестовым API и заглушкой SoundCloud. Исправлено падение существующей страницы новостей при пустой коллекции. Эти тестовые сборки нельзя переносить на рабочий сайт: на тестовом/рабочем окружении нужно собрать заново с его API.
- Страница входа визуально проверена в браузере в локальном Next.js-приложении. Полный визуальный прогон авторизованного кабинета и админки ещё нужен на тестовом окружении.
- Бэкенд проверен на загрузку всех маршрутов без запуска сервера и подключения к рабочей базе.

## Настройка отдельного тестового окружения

Использовать отдельную тестовую MongoDB replica set: операции баллов используют MongoDB-транзакции. Создать коллекции и индексы до включения программы. Текущая конфигурация Mongoose создаёт индексы при подключении, если autoIndex не выключен; при выключенном autoIndex их нужно создать при подготовке окружения.

Для тестов использовать Node.js 20 или новее. В бэкенде после установки зависимостей: `npm test` и `npm run test:integration`. Интеграционный тест сам создаёт и удаляет тестовую MongoDB; при первом запуске скачивается MongoDB. Почта в нём заменена заглушкой, рабочие подключения не используются.

Настройки бэкенда перечислены в `back/.env.example`. Для кабинета нужны:

```
PASSPORT_SECRET=<случайная строка не короче 32 символов>
CLIENT_ORIGINS=https://test-client.example.com
ADMIN_ORIGIN=https://test-admin.example.com
HOST=https://test-api.example.com
HOST_LINK=https://test-client.example.com
PASSPORT_WORKER_ENABLED=true
CAMPAIGN_SENDING_ENABLED=false
```

Сохранить существующий `JWT` для авторизации администраторов. `PASSPORT_SECRET` — отдельный секрет кабинета и ссылок отписки. В локальный `.env` добавлен случайный PASSPORT_SECRET, его значение не выведено и не включено в архив.

При HTTPS-развёртывании выставить `NODE_ENV=production`. Сайт и API должны быть на одном site, например `test.example.com` и `api.test.example.com`, поскольку cookie использует SameSite=Lax. При размещении на разных несвязанных доменах нужно отдельно настроить безопасную cookie/CSRF-схему.

Клиент: `NEXT_PUBLIC_API_URL=https://test-api.example.com/api`.

Админка: `REACT_APP_API_URL=https://test-api.example.com/api`.

Сначала проверять с тестовыми ключами LiqPay и отдельным отправителем почты. В этой сессии рабочие подключения, которые были внесены в `.env`, для проверки базы/платежей/почты не использовались. Реальные начисления и рассылки не запускались.

В админке включить программу и задать экономику баллов. По умолчанию программа отключена; примерные значения — 5% от покупки, 1 балл = 1 грн, предел скидки 30%, контент 100 баллов. Эти значения не являются утверждёнными правилами бизнеса.

Для всех прошлых покупок есть обработка партиями по 25 в админке либо команда в бэкенде:

```
node scripts/import-history.js
node scripts/import-history.js --apply
```

Первая команда сохраняет отчёты без начисления. Вторая проверяет оплаты повторно и начисляет. До запуска на рабочей базе нужно проверить отчёт на тестовой копии. Обе команды обращаются к LiqPay за статусом платежей. Повторное начисление блокирует уникальный источник операции.

## Ограничения до рабочего запуска

- Реальный LiqPay callback, генерацию PDF и доставку писем нужно проверить на тестовом окружении целиком. Интеграционные проверки выше изолировали почту и не выполняли реальные платежи/рендер PDF.
- Возвраты билетов не входят в функциональность по политике проекта и не являются условием запуска. Обработка неуспешной оплаты и освобождение зарезервированных баллов остаются. Защитная обработка технического статуса `reversed` от платёжного провайдера сохраняется; она не создаёт возможность клиентского возврата.
- У старых заказов флаг `isTicketsGenerated` сохраняется как признак выдачи. Если старый код поставил его до сбоя, такой случай требует отдельного разбора, чтобы не выдать повторные билеты.
- Резерв освобождается после подтверждённого неуспеха оплаты. Незавершённые платежи остаются в резерве до финального статуса провайдера; автоматическое истечение неподтверждённого заказа по времени ещё не введено.
- Gmail/Nodemailer использован как доступный транспорт. Для массовых рассылок на рабочей базе нужен выбранный провайдер, настройка домена и обработка отказов/жалоб. Текущий `sent` означает принятие SMTP-сервером, а не доставку. Автоматические bounce/complaint webhooks ещё не подключены. Неоднозначная отправка после сбоя отмечается `uncertain` и автоматически не повторяется.
- Старым клиентам подписка на маркетинг автоматически не включается. Существующий email сам по себе не добавляет человека в кампанию. Источник старых согласий нужно проверить и при наличии перенести отдельно.
- По запросу владельца отправка заявок в Telegram и её доступы сохранены в клиентском коде, как в исходном проекте. Telegram-переменные в `.env` не нужны.
- Старые архивные формы покупки, использующие устаревшие позиционные аргументы вместо `ticketCart`, не получили блок списания баллов. Действующие формы с `ticketCart` обновлены.
- Stories, автоматическое объединение аккаунтов, SMS-вход, товары/скидки на мерч и визуальный редактор письма с перетаскиванием блоков не включены в эту версию.

Эту версию можно проверять на отдельном тестовом окружении. Для рабочего запуска остаются сквозная проверка реальной интеграции оплаты/почты и выбор транспорта массовых рассылок.
